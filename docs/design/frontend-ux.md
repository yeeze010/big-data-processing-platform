# 前端与交互设计说明

## 当前视觉方向

当前前端采用 Swiss 高密度工程控制台方向：纯白与冷灰表面、Yves Klein Blue 单一强调色、细网格和 1px 分隔线。首屏将实时数据流、服务健康、事件轨、吞吐、验收闸口与失败记录置于同一控制视野，避免通用后台换皮。

核心交互包括：

- 点击工作流节点打开节点检查器，查看类型、状态和上下游数量。
- 按状态筛选任务实例，并执行重跑、暂停、人工确认成功等状态流转。
- 使用全局搜索筛选任务、资产和数据源。
- 切换紧凑视图，提高大屏工程监控的信息密度。
- 表单提交、刷新和报表生成均提供可访问的状态反馈。
- 验收闸口、发布闸口、交付材料与剩余风险直接在页面内展示，不把验收闭环留给 README 单独承担。

## 1. 设计方向

使用 `frontend-design` 的 Swiss 方向：白色与浅灰底、1px 规则线、左对齐信息层级、单一蓝色强调色。该方向适合高密度数据后台，能让数据源、任务实例、质量报告和审计记录保持清晰、可扫描、可验收。

## 3. 页面模板

### 3.1 列表页

- 顶部：页面标题、主操作按钮。
- 筛选区：关键字段、状态、负责人、时间范围。
- 表格区：固定首列、状态列、操作列。
- 批量操作区：启用、暂停、删除、导出。
- 空状态：说明为什么为空，并提供创建入口。
- 错误状态：展示原因和重试按钮。

### 3.2 详情页

- 顶部：对象名称、状态、负责人、最近更新时间。
- 分页签：基础信息、运行记录、关联资产、审计日志。
- 右侧操作：编辑、测试连接、触发、暂停、归档。

### 3.3 编排画布

- 左侧：节点类型库，包含采集、同步、清洗、转换、聚合、质量检测、通知。
- 中间：DAG 画布，支持节点拖拽、连线、参数编辑。
- 右侧：节点属性面板。
- 底部：校验结果、发布检查、版本变更。

## 4. 关键交互

| 场景 | 交互要求 |
|---|---|
| 数据源连通测试 | 按钮进入 loading，完成后展示成功/失败原因 |
| 工作流发布 | 先执行 DAG 校验，失败时定位到问题节点 |
| 任务重跑 | 二次确认，说明影响范围和重跑参数 |
| 异常数据关闭 | 必填处理原因和复核人 |
| 文件下载 | 敏感文件提示审计记录 |
| 批量授权 | 展示将被影响的用户、角色、数据范围 |

## 5. 可访问性与响应式

- 所有表单字段使用可见 label，不只依赖 placeholder。
- Icon-only 操作必须提供 `aria-label` 或文本按钮。
- 错误提示靠近字段展示，页面顶部可提供错误摘要。
- 焦点顺序与视觉顺序一致。
- 状态不能只靠颜色表达，必须同时有文字。
- 移动端优先展示核心数据，次要列折叠到详情抽屉。
