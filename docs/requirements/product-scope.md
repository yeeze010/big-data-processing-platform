# 大数据处理平台需求规格说明

## 1. 项目定位

大数据处理平台面向企业内部的数据工程、业务分析、平台运维和审计团队，提供从数据源接入、数据采集、同步处理、清洗转换、聚合建模、工作流编排、任务调度、数据质量、异常数据处置、数据资产目录、血缘分析到权限审计的一体化管理入口。

平台首期定位为可开发、可演示、可验收的管理后台 MVP，优先覆盖数据处理链路可视化和治理闭环，不在首期实现完整 Spark/Flink 执行引擎，而是通过执行适配层预留集成能力。

## 2. 用户角色

| 角色 | 主要目标 | 关键权限 |
|---|---|---|
| 平台管理员 | 维护租户、用户、角色、菜单、系统参数和资源配额 | 全局管理、授权、审计查看 |
| 数据工程师 | 接入数据源、创建采集/同步/清洗/聚合任务、维护工作流 | 数据源管理、任务配置、运行触发 |
| 数据分析师 | 查看数据资产、质量报告、指标报表和处理产物 | 资产查看、报表查看、文件下载 |
| 运维工程师 | 监控任务队列、服务健康、失败重试、告警处理 | 运维监控、任务重跑、告警关闭 |
| 数据治理专员 | 维护质量规则、异常数据、血缘和资产目录 | 质量规则、资产治理、异常闭环 |
| 审计员 | 查看登录、操作、权限变更、数据访问和导出记录 | 只读审计、导出审计报告 |

## 3. 核心业务流程

1. 数据工程师创建数据源并完成连通性测试。
2. 平台保存凭据引用，敏感凭据加密存储，不在接口中明文返回。
3. 数据工程师创建采集任务，配置来源、目标、字段映射、增量字段和预检查规则。
4. 数据工程师将采集、清洗、转换、聚合节点编排为工作流 DAG。
5. 工作流发布后进入调度中心，支持定时触发、手动触发、补数和依赖触发。
6. 调度器生成任务实例，执行适配层提交到批处理、流处理或本地任务执行器。
7. 每个节点写入运行日志、输入输出指标、耗时、错误信息和产物位置。
8. 质量规则在任务后置阶段运行，生成质量报告和异常数据样本。
9. 异常数据进入问题池，按负责人派单、处理、复核、关闭。
10. 任务产物登记到数据资产目录，更新表、字段、标签、负责人、版本和血缘关系。
11. 告警中心根据失败、延迟、质量阈值、资源容量和权限风险生成通知。
12. 审计中心记录登录、配置变更、任务操作、数据访问、文件下载和导出行为。

## 6. 报表指标

| 指标 | 口径 | 用途 |
|---|---|---|
| 今日处理记录数 | 当日成功写入目标表或文件的记录数 | 总览运营 |
| 任务成功率 | 成功任务实例 / 总任务实例 | 调度稳定性 |
| 质量通过率 | 通过规则数 / 执行规则数 | 数据治理 |
| 平均任务耗时 | 完成实例总耗时 / 完成实例数 | 性能趋势 |
| 失败重试成功率 | 重试后成功实例 / 重试实例数 | 运维闭环 |
| 数据源可用率 | 可连接数据源 / 总数据源 | 接入健康 |
| 告警关闭时长 | 告警关闭时间 - 告警创建时间 | 响应效率 |
| 资产覆盖率 | 已登记资产 / 产物总数 | 治理覆盖 |
| 审计完整率 | 关键操作有审计记录比例 | 合规验收 |

## 7. 告警通知规则

| 场景 | 触发条件 | 等级 | 默认处理 |
|---|---|---|---|
| 任务失败 | 工作流实例或节点失败 | 高 | 通知负责人，允许重跑 |
| 连续失败 | 同一工作流连续失败 3 次 | 高 | 升级给运维负责人 |
| 调度延迟 | 实际开始时间晚于计划 15 分钟 | 中 | 通知运维 |
| 质量阈值 | 质量通过率低于配置阈值 | 中/高 | 生成异常数据问题 |
| 数据源不可用 | 连通性测试失败或心跳超时 | 高 | 暂停相关任务 |
| Kafka 延迟 | 消费延迟超过阈值 | 中 | 通知平台运维 |
| 对象存储容量 | 容量超过 80% | 中 | 通知运维扩容 |
| 敏感导出 | 敏感资产下载或批量导出 | 中 | 通知审计员 |
| 权限变更 | 高权限角色授权变更 | 高 | 写入审计并通知管理员 |

## 8. 文件附件管理

- 存储对象：采集文件、任务日志、质量报告、异常样本、导出文件、验收附件。
- 元数据：文件名、大小、类型、Bucket、Object Key、版本、标签、上传人、授权范围、过期时间。
- 权限：继承项目空间数据范围，敏感文件需要下载审计。
- 生命周期：临时导出文件默认 7 天过期，验收归档文件长期保留。
- 安全：下载链接短期有效，不在接口中暴露对象存储永久凭据。

## 9. 非功能要求

- 普通列表接口 2 秒内响应，关键看板接口 1 秒内响应。
- 任务触发接口 1 秒内返回提交结果，实际执行异步完成。
- 所有 P0 操作必须写审计日志。
- 页面需要具备加载、空状态、错误状态和确认提示。
- 管理后台适配 375、768、1024、1440 宽度。
- 凭据、Token、下载链接和导出文件需要最小权限控制。
